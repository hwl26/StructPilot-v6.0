# 📚 知识库与经验库关系说明

## 核心概念区分

### **1. Knowledge Base（知识库）— 官方权威知识**

**位置：** `knowledge_base/` 目录

**内容来源：**
- 官方文档（cryoSPARC、RELION 官方文档）
- 权威教程和指南
- 软件使用说明
- 标准操作流程（SOP）

**特点：**
- ✅ **只读** — 用户不能修改
- ✅ **权威** — 来自官方或专家验证
- ✅ **结构化** — JSON/JSONL 格式，便于检索
- ✅ **RAG 来源** — 对话时通过向量检索提供参考

**文件：**
```
knowledge_base/
├── qa/
│   ├── formal_answers.jsonl      # 官方 Q&A
│   └── runtime_answer_index.json # 快速检索索引
├── flows/
│   ├── relion_stage_cards.json   # RELION 工作流卡片
│   └── stage_navigation_index.json # 流程导航
└── importer.py                    # 知识库导入器
```

**用途：**
- AI 对话时的参考资料
- 参数向导的默认值
- SOP 卡片的数据源

---

### **2. Lab Board / Lab Experience（实验室经验库）— 用户贡献经验**

**位置：** `runtime/lab_board/posts.json`

**内容来源：**
- 实验室成员的实践经验
- 问题解决方案
- 参数优化心得
- 特殊场景处理

**特点：**
- ✅ **可写** — 成员可以贡献经验
- ✅ **审核制** — 管理员审核后才公开
- ✅ **实践导向** — 来自真实实验场景
- ✅ **本地化** — 针对特定实验室的设备和流程

**数据结构：**
```json
{
  "entries": [
    {
      "id": "exp001",
      "title": "Motion Correction 报错解决方案",
      "category": "troubleshooting",
      "step": "cp_02",
      "symptoms_text": "local motion too large",
      "solution": "将 B-factor 调高到 500-800",
      "author": "张三",
      "date": "2025-01-20",
      "source": "user_contributed",  // 用户贡献
      "status": "approved"           // 已审核通过
    },
    {
      "id": "official001",
      "title": "CTF 估计标准流程",
      "category": "sop",
      "step": "cp_03",
      "solution": "...",
      "source": "official",           // 官方内容
      "status": "approved"
    }
  ]
}
```

**用途：**
- 知识库页面展示（已审核的经验）
- 成员之间的经验传承
- RAG 检索的补充来源（可选）

---

### **3. Forum（论坛/讨论区）— 即时问答交流**

**位置：** `runtime/forum/forum_posts.json`

**内容来源：**
- 成员的即时提问
- 其他成员的回答
- 评论和讨论

**特点：**
- ✅ **实时** — 即问即答
- ✅ **开放** — 所有成员可见
- ✅ **互动** — 支持点赞、采纳答案、评论
- ✅ **临时性** — 解决即时问题，不一定沉淀为经验

**关系：**
- 论坛中的优质问答 → 可以**提炼为经验** → 贡献到经验库
- 经验库中的内容 → 可以在论坛中**引用和讨论**

## 🔄 数据流转

### **场景1：新手提问**
1. 新手在**论坛**提问："Motion Correction 报错 local motion too large 如何解决？"
2. 老成员回答："将 B-factor 调高到 500-800"
3. 管理员看到这是通用问题，**提炼为经验**，贡献到**经验库**
4. 审核通过后，所有成员在**知识库页面**可以看到这条经验
5. 以后其他人遇到同样问题，AI 对话时可以**检索到这条经验**

### **场景2：官方知识导入**
1. 管理员从 cryoSPARC 官网下载最新文档
2. 使用 `knowledge_base/importer.py` **导入到知识库**
3. 知识库内容自动**索引**，便于 RAG 检索
4. 用户对话时，AI 自动引用官方知识回答

### **场景3：实验室首次部署**
1. 实验室安装 StructPilot
2. 默认只有**官方知识库**（Knowledge Base）
3. **经验库为空**（Lab Board），等待成员贡献
4. 管理员点击「**从头开始**」，确认清空经验库
5. 实验室成员逐步积累自己的经验

## 🎯 "从头开始"按钮的作用

### **问题背景**
- 演示或测试时，经验库可能包含**示例数据**
- 不同实验室的设备、流程、经验**差异很大**
- 新实验室希望**从零开始**积累自己的经验

### **功能说明**
**"从头开始"按钮会：**
1. ✅ **保留官方知识库**（Knowledge Base）— 不动
2. ✅ **清空用户贡献的经验**（Lab Board 中 `source: "user_contributed"` 的条目）
3. ✅ **保留官方基础经验**（Lab Board 中 `source: "official"` 的条目）
4. ✅ **自动备份**现有经验库到 `runtime/knowledge_base/backups/`

**不会影响：**
- ❌ **不清空论坛**（Forum）— 历史讨论保留
- ❌ **不清空个人笔记**（User Notes）— 个人数据保留
- ❌ **不修改知识库**（Knowledge Base）— 官方知识不动

### **使用场景**
```
场景1：演示环境转生产
- 演示时创建了很多测试经验
- 正式使用前，点击「从头开始」清空测试数据
- 实验室从零开始积累真实经验

场景2：跨实验室部署
- A 实验室的经验库不适用于 B 实验室
- B 实验室点击「从头开始」清空 A 的经验
- B 实验室积累自己的经验

场景3：定期清理
- 经验库积累了很多过时内容
- 管理员点击「从头开始」重新开始
- 保留有价值的官方基础内容
```

## 🎨 "抽象框架"按钮的作用

### **问题背景**
- StructPilot 目前专注于 **cryoEM 单颗粒分析**
- 但框架设计是**通用的**：工作流 + 知识库 + 论坛 + AI 辅助
- 其他领域也有类似需求（CryoET、蛋白质组学、材料学等）

### **功能说明**
**"抽象框架"按钮会：**
1. ✅ **生成领域模板**（JSON配置文件）
2. ✅ **定义工作流步骤**（适配该领域）
3. ✅ **配置软件列表**（该领域常用软件）
4. ✅ **生成 README**（快速启动指南）

### **预定义领域**
- **CryoET**（冷冻电子断层扫描）
  - 工作流：倾斜系列采集 → 层析重建 → 模板匹配 → 亚层析平均
  - 软件：IMOD、Etomo、Warp、emClarity

- **蛋白质组学**
  - 工作流：样品制备 → 质谱采集 → 数据库搜索 → 定量分析
  - 软件：MaxQuant、Proteome Discoverer、Mascot

- **材料学**
  - 工作流：样品制备 → 成像 → 结构表征 → 性能测试
  - 软件：Materials Studio、VESTA、ImageJ

- **艺术制作**
  - 工作流：灵感收集 → 草图设计 → 制作 → 展示
  - 软件：Blender、Substance Painter、Unity

### **使用场景**
```
场景1：CryoET 实验室想用 StructPilot
1. 管理员点击「抽象框架」→ 选择「CryoET」
2. 生成 CryoET 领域模板（JSON + README）
3. 复制模板到 runtime/active_domain_config.json
4. 重启应用，自动适配 CryoET 工作流
5. 清空经验库，开始积累 CryoET 经验

场景2：材料学实验室自定义
1. 管理员选择「自定义领域」
2. 填写：领域名称「扫描电镜分析」
3. 定义工作流：样品制备 → SEM 成像 → EDS 分析 → 数据处理
4. 配置软件：AZtec、Thermo Scientific、ImageJ
5. 生成模板，启动应用
```

## 💡 总结

| 功能 | 知识库 (KB) | 经验库 (Lab Board) | 论坛 (Forum) |
|------|-------------|-------------------|--------------|
| **内容来源** | 官方文档 | 实验室经验 | 即时问答 |
| **权限** | 只读 | 成员贡献，管理员审核 | 所有成员可见 |
| **数据结构** | 结构化JSON | 结构化JSON | 问答格式 |
| **用途** | RAG检索、SOP | 知识传承、经验查询 | 即时互动 |
| **是否清空** | ❌ 不清空 | ✅ 「从头开始」清空用户贡献部分 | ❌ 不清空 |

---

**"从头开始"按钮** = 清空**经验库**的用户贡献部分，让实验室从零积累自己的经验

**"抽象框架"按钮** = 将 StructPilot 适配到**其他领域**，生成领域专属配置模板
